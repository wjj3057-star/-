# 오늘출석 1.3.2 정밀 검토 기록

검토 완료: 2026-10-12. 대상: Android 앱 1.3.2, `versionCode 8`.

## 검토 범위

운영 코드의 Java·JavaScript, 화면 자산, Manifest·리소스, 빌드 스크립트와 CI를 다시 검토했다. 설정 저장과 실패 복구, 체크 자동 저장, 테마와 권한 표시, 날짜 전환과 과거 기록, 학생·학부모 등록, 연락처의 비동기 응답, SMS 결과·재전송·수신 동의, 백업 복원·내보내기, 입력 검증과 WebView 접근 제한을 확인했다.

기존 테스트에 더해 실제 문제가 발생하던 조건을 재현하는 회귀 테스트를 추가했다. 아래의 “재현”은 테스트 환경에서 수정 전 실패와 수정 후 통과를 확인한 항목이다. 실기기 확인과는 구분한다.

## 발견 및 수정

| 항목 | 확인한 문제 | 수정과 검증 |
| --- | --- | --- |
| 문자 성공 기록 | 같은 분할 문자에 성공 응답 뒤 모순되는 실패 응답이 오면 성공이 실패로 바뀌었다. 재현 완료. | 확인된 성공을 유지하고 같은 응답은 무시한다. 실패 뒤 지연 성공은 정상 반영한다. |
| 재전송 경쟁 조건 | 재전송을 준비하는 사이 이전 시도의 성공이 도착해도 새 문자가 통신망에 전달될 수 있었다. 재현 완료. | 마지막 발송 직전에 저장된 성공 기록을 다시 확인한다. 결과 처리와 발송 직전 확인을 직렬화해 이전 성공이 확인된 재전송은 취소한다. |
| 저장 성공 판정 | 파일 교체 API가 예외 없이 실패하면 저장 성공을 반환했다. 임시 파일·교체 실패를 모사한 환경에서 재현했다. | 파일 동기화와 저장된 바이트 검증 후 완료를 알린다. 부분 쓰기·교체 실패 시 기존 설정을 유지하며, 문자 발송 기록 저장이 확인되지 않으면 발송하지 않는다. |
| 연락처 재조회 | 연락처 선택창을 다시 열어 조회를 기다리는 동안 검색하면 이전 목록의 번호가 선택 가능했다. 재현 완료. | 새 요청 시작과 창 닫기에서 목록을 비운다. 로딩·오류 상태를 검색 중에도 유지한다. |
| 대량 자동 등록 | 기존 학생 450명·후보 180명에서 선택 항목 81,360개를 한꺼번에 생성했다. | 20명씩 페이지를 나누고 기존 학생 검색 결과를 제한한다. 같은 조건의 초기 선택 항목은 60개다. 이름·번호·목록 번호 검색, 전체 선택·해제, 페이지 간 입력·체크 보존을 검증했다. |
| 등록 검색 키보드 | 기존 학생 검색에서 Enter가 등록 제출로 이어질 수 있었다. | Enter는 학생 선택으로 초점을 옮기며 등록을 제출하지 않는다. 회귀 테스트로 확인했다. |
| 백업과 화면 재생성 | 내보낼 내용이 Activity 메모리에만 있어 파일 선택 중 화면 재생성 시 사라질 수 있었다. 화면 준비 전 복원 응답도 유실될 수 있었다. 코드 검토로 확인했다. | 앱 전용 임시 파일과 복원 가능한 토큰으로 내보낼 내용을 유지한다. 화면 준비까지 결과를 보관한 뒤 한 번만 전달한다. 재생성 모사·취소 정리·경로와 크기 제한·전달 순서를 테스트했다. |
| 오류 안내 | 학생·기록 한도 초과와 문자 기록 저장 실패의 안내가 모호했다. | 구체적인 한국어 오류를 표시한다. 한도를 넘은 입력을 거절하면서 원본을 바꾸지 않는지 확인했다. |

## 실행한 검증

| 검증 | 결과 |
| --- | --- |
| Node 단위 테스트 (`core.test.cjs`, `contacts-sms.test.cjs`) | 27개 통과 |
| Java SMS 규칙 (`SmsRulesTest`) | 통과: 전화번호 정규화·중복 키·문구 치환 |
| 네이티브 회귀 (`native_sms.py`) | 4개 실행 묶음 통과: `NativeSmsTest`, `StoreTest`, `DeepSmsTest`, `DocumentFlowTest` |
| 브라우저 화면 테스트 | 7개 묶음 모두 통과: `ui`, `contacts-ui`, `settings-ui`, `midnight-ui`, `theme-autosave-ui`, `audit-ui`, `deep-audit-ui` |
| 좁은 화면·테마 | 320px 등록창 가로 넘침 검사 통과. 한글 글꼴을 적용한 라이트·다크 화면 확인 |
| 정적 검사 | JavaScript 문법, Python 구문, Android XML, `git diff --check` 통과 |
| APK | Android 35 도구로 빌드·정렬·서명 검증 완료. 패키지·버전·기존 서명 일치 확인. APK의 화면 자산과 테스트한 소스가 바이트 단위로 일치 |

네이티브 테스트는 운영 Java 코드에 Android API 모의 구현을 연결해 실행했다. 실제 전화번호를 조회하거나 문자를 전송하지 않았다. 회귀 항목에는 성공·실패·분할 응답·지연 응답·중복·재전송·자동 발송 중단·수신 동의 변경·저장 실패·손상 데이터·화면 준비 전 결과 전달이 포함된다.

화면 테스트는 Chromium과 모의 Android 브리지를 사용했다. 자정과 정오, 연말, 절전 후 복귀, 설정 재실행과 자동 저장 실패 복구, 테마, 권한 버튼, 연락처 재시도와 대량 등록을 확인했다. 로컬 검증 결과이며 원격 GitHub Actions의 실행 결과를 의미하지 않는다.

## 남은 실기기 확인 범위

물리 Android 기기·통신사 망에서의 SMS 발송, 실제 연락처 권한 화면, 제조사 절전 동작, OS가 파일 선택 도중 Activity·프로세스를 재생성하는 동작은 이 환경에서 직접 실행하지 못했다. 그 조건의 내부 로직은 모의 환경에서 검증했지만 실기기 검증을 대체하지 않는다.

문자 “발송 완료”는 통신망 발송 결과이며 수신자의 실제 수신·읽음 확인이 아니다. 이전 문자가 이미 통신망에 전달된 후에는 취소할 수 없다. 응답을 잃은 문자도 자동 재전송하지 않는다. 이번 검토에서 재현한 결함은 수정했으며, 모든 기기와 상황에 오류가 없다고 보장하는 결과는 아니다.
