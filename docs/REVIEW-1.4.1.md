# 오늘출석 1.4.1 전체 검토

완료일: 2026-10-14. 버전: `1.4.1` / `versionCode 11`.

## 확인하고 수정한 문제

| 문제 | 재현 조건 | 수정 결과 |
| --- | --- | --- |
| 이름 변경 후 검색 누락·정렬 불일치 | 이미 출석을 체크한 학생의 이름을 수정하면 출석부는 기록에 남은 예전 이름만 검색·표시했다. | 현재 학생 이름으로 표시하고 가나다순으로 정렬한다. 선택 날짜의 기록 이름도 검색할 수 있다. 이름이 다르면 카드에 기록 이름을 함께 안내하며, 과거 기록과 CSV는 변경하지 않는다. |
| 출석 체크 후 키보드 초점 소실 | 키보드로 출석 버튼을 누르면 저장 과정의 화면 교체로 초점이 본문으로 이동했다. | 저장 성공 후 같은 학생·같은 상태 버튼에 초점을 복구한다. Tab 키로 다음 상태 버튼에 계속 이동할 수 있다. |
| 작동하지 않는 되돌리기 버튼 잔류 | 출석을 체크한 직후 문자 설정 체크를 자동 저장하면 이전 되돌리기는 무효화되지만 버튼은 남았다. | 성공한 별도 저장이 이전 되돌리기를 무효화하면 버튼을 제거한다. 설정 저장이 실패한 경우에는 원래 출석의 되돌리기를 유지한다. |
| 서명키 경로 오류로 새 키 생성 | 존재하지 않는 `--keystore` 경로로 빌드하면 새 키가 자동 생성되어 기존 설치본에 업데이트할 수 없는 APK를 만들었다. | 명시한 키가 없으면 컴파일 전에 중단하고 기존 출력 파일을 보존한다. 새로운 서명을 의도한 경우에만 `--create-keystore`로 허용한다. |

앞의 세 문제는 수정 전 화면 테스트에서 재현했다. 서명키 문제는 별도의 임시 경로에서 기존 빌드 동작을 실행해 새 키가 생성되는 것을 확인했다. 재현용 키와 APK는 배포하지 않았으며 제거했다.

## 검토 및 검증

출석·날짜·통계·백업 데이터 로직, 화면 저장과 실패 복구, 연락처 자동 등록, 문자 요청·결과 수신·중복 방지, Android 저장소와 파일 전달, 빌드·서명을 검토했다. 수정 후 전체 기존 회귀 검사를 다시 실행했다.

| 항목 | 결과 |
| --- | --- |
| Node 단위 검사 | 30개 통과. 이름 변경 검색·정렬·과거 기록 보존, 기존 연락처·문자 규칙, 4,000회 출결 변경, 백업 왕복 포함 |
| 화면 검사 | 총 10개 묶음 통과: `ui`, `contacts-ui`, `settings-ui`, `midnight-ui`, `theme-autosave-ui`, `audit-ui`, `deep-audit-ui`, `scale-ui`, `attendance-layout-ui`, `post-ui-audit` |
| 새 화면 회귀 | 이름 변경 후 새 이름·옛 이름 검색, 가나다순, 저장 뒤 키보드 초점·Tab 이동, 설정 저장 성공/실패에 따른 되돌리기 4개 시나리오 통과 |
| 대량 데이터·사용성 | 5,000명 목록, 페이지 밖 일괄 체크·되돌리기, 검색, 자정 전환, 입력 보존, 다크 모드 및 320·390·800px 화면 검증 통과 |
| Java 문자 규칙 | 번호 정규화, 중복 키, 템플릿 치환 검사 통과 |
| 네이티브 회귀 | 문자 성공·실패·분할·지연·중복 응답, 재시도 경합, 동의 취소, 저장 실패·손상 보호, 화면 재생성 중 백업 전달 등 4개 묶음 통과 |
| 빌드 경로 회귀 | 누락된 명시적 서명키 차단, 키 미생성, 기존 출력 파일 보존 통과 |
| 정적 검사 | JavaScript·Python 구문, Android XML, diff 검사 통과 |
| APK | 컴파일·정렬·서명 검증 통과. 패키지·버전·최소/대상 API 확인, 번들 자산 5개와 최종 소스 일치 확인 |

화면 검사는 Chromium과 모의 Android 브리지를 사용했다. 네이티브 회귀 검사는 Android API를 대체한 테스트 환경에서 실제 앱의 Java 코드를 실행했다. 실제 연락처를 읽거나 SMS를 보내지 않았다. 실기기·통신사 망·제조사 절전 정책 검증과 원격 CI 성공을 의미하지 않으며, 모든 환경에서 버그가 없음을 보장하지 않는다.

채팅으로 제공한 **1.4.0·1.3.3과 같은 서명키**로 빌드했다. **1.2.0과는 서명이 다르며 그 위에 업데이트 설치할 수 없다.** 1.2.0의 원래 개인 서명키는 현재 확보하지 못했다. 1.2.0 사용자는 기존 앱의 `설정 → 전체 데이터 백업`으로 JSON 파일을 확보한 뒤 새 앱 설치 및 복원을 진행해야 한다. 백업 전에 기존 앱을 삭제하면 안 된다. 복원 시 문자 자동 발송은 꺼진 상태로 시작한다.

개인 서명키는 GitHub 저장소에 포함하지 않는다. CI의 임시 키 APK는 기존 배포 앱의 업데이트용이 아니다.
