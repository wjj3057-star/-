# 오늘출석 1.3.3 반복 검토 기록

검토 기간: 2026-10-12~13. 대상: Android 앱 1.3.3, `versionCode 9`.

## 범위와 반복 검토 방법

1.3.2의 운영 Java·JavaScript 전체, Manifest·리소스·스타일, 빌드 스크립트·CI와 기존 테스트를 다시 읽었다. 설정 저장과 실패 복구, 체크 자동 저장, 테마·권한 표시, 자정과 날짜 전환, 출결·되돌리기·과거 기록, 연락처 등록, SMS 결과·재전송·동의 변경, 백업과 화면 생명주기, 데이터 한도·입력 검증·WebView 접근 제한을 검토했다.

첫 검토에서 찾은 시간 계산·화면 재생성·대량 목록 문제를 수정하고 회귀 검증을 실행했다. 수정된 동작을 다시 검토하면서 과거 기록에서 학생을 찾아가는 페이지 이동 문제를 추가로 고쳤다. 마지막 네이티브 재검토에서는 문자 기록 저장 중 자동 발송 끄기가 지연되는 조건을 재현하고, 잠금 범위를 수정한 뒤 네이티브 전체 회귀를 다시 통과시켰다.

아래에서 재현했다고 적은 항목은 모의 환경에서 수정 전 실패와 수정 후 통과를 확인했다는 뜻이다. 코드 검토로 확인한 문제와 물리 기기 검증은 구분한다.

## 발견 및 수정

| 항목 | 문제와 확인 방법 | 수정 결과 |
| --- | --- | --- |
| SMS 결과 대기 시간 | 기록 생성 시각부터 대기를 계산해 준비가 길어진 요청이 발송 직후부터 결과 불명·재전송 가능으로 표시될 수 있었다. 생성 시각을 3분 전으로 둔 회귀 조건에서 재현했다. | 기록 생성과 발송 요청의 시각을 분리한다. 발송 준비 후반에 요청 시각을 기록하고 이를 대기 시간의 기준으로 사용한다. |
| 휴대폰 시간 변경 | 실행 중 시스템 시계를 앞뒤로 바꾸면 SMS 대기가 조기에 끝나거나 늘어날 수 있었다. | 같은 프로세스에서는 단조 경과 시간을 사용한다. 재시작한 기록과 구버전 기록은 저장된 요청·생성 시각으로 판단한다. 지연 성공 응답은 계속 정상 반영한다. |
| 준비 중 자동 발송 끄기 | 마지막 재검토에서 문자 기록을 저장하는 잠금이 설정 저장까지 막는 조건을 재현했다. | 기록 쓰기는 설정 잠금 밖에서 완료한다. 그 후 최신 발송 설정·학생·출결·수신 대상을 다시 확인하고 통신망에 전달한다. 준비 중 끄기가 반영되면 취소 기록을 남기고 전송하지 않는다. |
| 진행 중인 백업의 화면 재생성 | 비동기 파일 읽기·쓰기가 끝나기 전에 Activity가 재생성되면 이전 화면의 종료된 이벤트 큐가 결과를 버릴 수 있음을 코드 검토로 확인했다. | 구성 변경 시 이벤트 큐를 새 Activity에 연결한다. 새 화면이 준비될 때까지 순서대로 보관하고 한 번만 전달한다. 정상 종료 시 남은 이벤트는 정리한다. |
| 대량 학생 목록 | 5,000명에서 모든 학생 카드를 한 번에 생성하던 화면이 Chromium의 30초 페이지 로드 제한을 넘었다. | 출석부·학생 목록·학생별 월간 기록을 50명씩 표시한다. 검색·통계는 전체 데이터를 사용한다. 일괄 출석은 다른 페이지를 포함한 검색 결과 전체에 적용하며 확인창에서 범위를 안내한다. |
| 과거 기록에서 학생 찾기 | 페이지 분할 수정 후 학생의 과거 기록을 누르면 첫 페이지에 열려 해당 학생이 보이지 않을 수 있음을 후속 검토로 확인했다. | 해당 날짜와 학생이 있는 페이지로 이동해 그 학생의 버튼에 초점을 맞춘다. 검색·날짜·월 변경 시 페이지도 적절하게 초기화한다. |

기존의 중복 발송 방지와 저장 실패 시 발송 차단은 유지한다. 자동 발송 설정을 끄더라도 이미 통신망에 전달된 요청을 회수하는 것은 아니다.

네이티브 검증은 운영 Java에 Android API 모의 구현을 연결했다. 비동기 성공·실패·분할 응답·지연 응답·중복 콜백·재시도·준비 중 성공 응답·발송 중단·수신 동의·저장 실패·손상 데이터·이벤트 연결 교체를 포함한다. 실제 연락처를 읽거나 문자를 전송하지 않았다.

화면 검증은 Chromium과 모의 Android 브리지를 사용했다. 설정 저장·자동 저장 실패 복구, 권한 버튼 숨김, 라이트·다크·시스템 테마, 자정·정오·연말·절전 복귀, 연락처의 늦은 응답·재시도·대량 등록 등 기존 회귀도 통과했다. 새 페이지 UI의 별도 육안 검수를 수행했다는 의미는 아니다. 결과는 로컬 실행 기준이며 GitHub Actions 실행 성공을 의미하지 않는다.

## 확인 범위의 한계

물리 Android 기기·통신사 망에서의 SMS, 실제 연락처 권한 화면, 제조사 절전 정책, OS의 실제 Activity 재생성은 직접 실행하지 못했다. 구성 변경 중 진행하던 파일 작업의 결과 전달을 모의 검증했지만, 프로세스가 강제 종료된 뒤 진행 중 작업이 자동 재개된다고 보장하지 않는다.

문자 “발송 완료”는 발송 결과 응답을 뜻하며 수신·읽음 확인이 아니다. 응답이 없는 문자는 자동 재전송하지 않는다. 이번 반복 검토에서 확인한 결함은 수정하고 관련 회귀를 통과시켰지만, 모든 기기와 모든 상황에서 오류가 전혀 없음을 증명한 결과는 아니다.
